# Gamepad (Stage 3) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Pads (Xbox, 8BitDo, DualShock 4, DualSense, Switch Pro, Moonlight's virtual pad) open and drive the overlay and switch monitor profiles, with nothing extra for the user to install.

**Architecture:** A pure Core state machine (`PadInterpreter`) turns button/axis events plus a clock into actions (toggle overlay, monitor TV/Desk, overlay commands); the self-test covers it. A thin Core service (`PadService`) runs SDL3's gamepad API on its own thread and feeds the interpreter. The App wires actions into `OverlayController` and `TrayController`, and shows pad hints and battery in the overlay.

**Tech Stack:** C# / .NET 10, SDL3 (official `SDL3.dll`, x64, vendored), our own `LibraryImport` wrapper, WPF App, dependency-free self-test.

**Spec:** `docs/superpowers/specs/2026-11-03-gamepad-design.md` (read it first). Python reference: `reference/python/app.py` section `CONTROLLER` (~line 636).

## Global Constraints

- Nothing for the end user to install: `SDL3.dll` ships next to the exe and is loaded **only** from `AppContext.BaseDirectory` (never PATH or the current directory). If it is missing or fails to load: log once with `Log.Error`, pads disabled, app otherwise unaffected.
- SDL is called only from the pad thread. Overlay work is marshalled to the UI thread; errors logged, never thrown (CLAUDE.md).
- Never use the Guide button; never react to Start+Back+LB+RB together.
- Timings: nav repeat first after 0.4 s, then every 0.12 s; hold Back alone 0.6 s → Settings. Triggers: pressed above 16000, released below 8000 (Python `TRIGGER_PRESS`/`TRIGGER_RELEASE`). Left stick: direction above 16000, released below 8000 on that axis.
- SDL3 enums (verify against the vendored version's headers): buttons SOUTH=0 EAST=1 WEST=2 NORTH=3 BACK=4 GUIDE=5 START=6 LEFT_STICK=7 RIGHT_STICK=8 LEFT_SHOULDER=9 RIGHT_SHOULDER=10 DPAD_UP=11 DPAD_DOWN=12 DPAD_LEFT=13 DPAD_RIGHT=14; axes LEFTX=0 LEFTY=1 RIGHTX=2 RIGHTY=3 LEFT_TRIGGER=4 RIGHT_TRIGGER=5; events GAMEPAD_AXIS_MOTION=0x650 BUTTON_DOWN=0x651 BUTTON_UP=0x652 ADDED=0x653 REMOVED=0x654. A = SOUTH, B = EAST (positional).
- User-facing text only via `Loc.T` with keys in both `.resx` files; config only via `ConfigStore.Update` (`controller_enabled` already exists).
- Checks after every task: `dotnet build OverlayUtils.sln` 0 warnings; `dotnet run --project tests/OverlayUtils.SelfTest` → `All N checks passed.`
- Manual testing rules: never send synthetic input, never stop or touch the user's running OverlayUtils or any other app, never change Windows settings. Pad checks that need a person pressing buttons are listed for the owner.
- Commit messages in English, ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **A pad unplugged (or its battery dying) while a button is held:** repeats stop, a half-pressed chord is forgotten, nothing fires later. Test in Task 1 (`PadRemoved`).
2. **Two pads at once:** Back on one pad and RB on the other must not toggle the overlay; each pad's chords are independent. Test in Task 1.
3. **Back held to open Settings, then RB pressed:** the overlay must not close on release; a consumed Back hold disarms the chord until Back is released. Test in Task 1.
4. **Trigger noise around the threshold:** a trigger resting near 16000 must not fire LT/RT repeatedly (hysteresis). Test in Task 1.
5. **`SDL3.dll` missing or the app running from Program Files (full mode):** the app starts, logs once, keyboard/tray still work; with the DLL present it loads from the exe folder. Manual check in Task 2 (rename the DLL in the debug output).

```csharp
public enum PadButton { A, B, X, Y, Back, Guide, Start, LeftStick, RightStick, LB, RB, DpadUp, DpadDown, DpadLeft, DpadRight }
public enum PadAxis { LeftX, LeftY, RightX, RightY, LeftTrigger, RightTrigger }
public enum PadActionKind { ToggleOverlay, MonitorTv, MonitorDesk, Command }
public readonly record struct PadAction(PadActionKind Kind, OverlayCommand Command = default);

public sealed class PadInterpreter
{
    public static readonly TimeSpan RepeatDelay = TimeSpan.FromSeconds(0.4);
    public static readonly TimeSpan RepeatInterval = TimeSpan.FromSeconds(0.12);
    public static readonly TimeSpan SettingsHold = TimeSpan.FromSeconds(0.6);
    public const short PressThreshold = 16000, ReleaseThreshold = 8000;
    public PadInterpreter(TimeProvider? time = null);
    public bool OverlayOpen { get; set; }
    public bool CombosEnabled { get; set; } = true;
    public IReadOnlyList<PadAction> ButtonDown(uint pad, PadButton button);
    public IReadOnlyList<PadAction> ButtonUp(uint pad, PadButton button);
    public IReadOnlyList<PadAction> Axis(uint pad, PadAxis axis, short value);
    public IReadOnlyList<PadAction> Tick();          // repeats and the Back hold; call every ~15 ms
    public void PadRemoved(uint pad);
    public uint? LastUsedPad { get; }
    public static int? BatteryLevel(int sdlPowerState, int percent); // 0..3 or null
}
```

Rules (Python `_check_combos`, `_overlay_armed`, `_back_hold`, `_nav_repeat`):
- State is per pad. Triggers past `PressThreshold` act as buttons LT/RT (down), back below `ReleaseThreshold` as up; between the two nothing changes. Left stick axes act as directions with the same thresholds (negative X = left, negative Y = up).
- **Toggle chord:** when Back and RB are both down and nothing else is down on that pad, the chord is armed; any other button going down disarms it. Releasing Back or RB while armed returns `ToggleOverlay` once. Works whether the overlay is open or closed.
- **Monitor combos:** overlay closed and `CombosEnabled`: DpadUp going down while Back is held → `MonitorTv`; DpadDown → `MonitorDesk`. Once per press.
- **Overlay open:** Dpad and stick directions → `Command(Up/Down/Left/Right)` on press, then repeats (`RepeatDelay`, then `RepeatInterval`); Left/Right repeats are `LeftRepeat`/`RightRepeat`, Up/Down repeats are `Up`/`Down`. A → `A`, B → `B`, LT → `PrevTab`, RT → `NextTab` (on press). Back held alone for `SettingsHold` → `Settings` once; that hold is then consumed: the toggle chord cannot arm until Back is released. X, Y, Start, stick clicks, LB alone do nothing.
- Overlay closed: navigation buttons produce nothing. Guide is ignored everywhere.
- `PadRemoved` forgets that pad's state (held buttons, repeats, armed chord, hold).
- `BatteryLevel`: SDL power state (−1 error, 0 unknown, 1 on battery, 2 no battery, 3 charging, 4 charged) and percent (−1 unknown): states 1 and 3 with percent ≥ 0 map to 0 (≤ 10), 1 (≤ 40), 2 (≤ 70), 3 (> 70); state 4 → 3; everything else → null.

**Interfaces:**
- Consumes: Task 1 `PadInterpreter`, `PadAction`, `PadButton`, `PadAxis`.
- Produces:

```csharp
public sealed class PadService : IDisposable
{
    public PadService(PadInterpreter interpreter);
    public void Start();                       // starts the pad thread; returns at once
    public event Action<PadAction>? ActionRaised;  // raised on the pad thread
    public event Action? StateChanged;         // pads added/removed or battery changed; pad thread
    public bool Available { get; }             // SDL loaded and initialised
    public int PadCount { get; }
    public int? BatteryLevel { get; }          // of LastUsedPad, else of any pad reporting one
    public bool OverlayOpen { set; }           // forwarded to the interpreter (thread-safe)
    public bool CombosEnabled { set; }
}
```

Implementation notes:
- `Sdl` registers `NativeLibrary.SetDllImportResolver` for its assembly so `"SDL3"` resolves only to `Path.Combine(AppContext.BaseDirectory, "SDL3.dll")`.
- Declarations needed: `SDL_SetHint`, `SDL_Init`, `SDL_Quit`, `SDL_GetError`, `SDL_WaitEventTimeout`, `SDL_OpenGamepad`, `SDL_CloseGamepad`, `SDL_GetGamepadPowerInfo`, `SDL_GetGamepadName` (name only for the log), plus an `SDL_Event` buffer read as a 128-byte blittable struct with explicit offsets (type `uint` at 0; gamepad `which` `uint` at 16; button `byte` at 20 and `down` `byte` at 21; axis `byte` at 20 and value `short` at 24 — verify against `SDL_events.h` of the vendored version). SDL3 functions returning `bool` use `[return: MarshalAs(UnmanagedType.U1)]`.
- Before `SDL_Init(SDL_INIT_GAMEPAD)`, set hint `SDL_JOYSTICK_ALLOW_BACKGROUND_EVENTS` = `"1"` (pads must work while a game has focus).
- The thread loops on `SDL_WaitEventTimeout(…, 15)`: ADDED opens the pad, REMOVED closes it and calls `PadRemoved`, buttons/axes go to the interpreter (SDL button/axis numbers mapped to `PadButton`/`PadAxis`; DPAD/shoulders/back as listed in Global Constraints), then `Tick()`; actions are raised via `ActionRaised`; battery polled every 30 s and on add/remove.
- Any exception on the thread is logged and the thread ends cleanly (pads disabled); `Dispose` stops the thread and calls `SDL_Quit` on it.
