# Games library (Stage 5) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Games tab listing installed games from Steam (incl. non-Steam shortcuts), Epic, GOG, Xbox / Game Pass, detected emulators and hand-added apps, launched with A, filtered with Y.

**Architecture:** Core readers parse each launcher's own registry entries and library files behind a small `IRegistryView` (so tests use fakes and fixture files); a pure `GameLibrary` merges, sorts and filters; the navigator gains a grid row kind. The App adds the Xbox reader (WinRT package catalog), a background `GameService`, the grid UI with artwork, and Settings → Games.

**Tech Stack:** C# / .NET 10, WPF, WinRT `Windows.Management.Deployment` (App only), dependency-free self-test.

**Spec:** `docs/superpowers/specs/2026-11-04-games-design.md` (incl. "Details settled before planning"). Python reference: `reference/python/app.py` section `LIBRERIA GIOCHI` (~1221-1442) and `_CoverGrid` (~3490-3594).

## Global Constraints

- **No hard-coded install paths.** Locations come from the launcher's registry values (Steam `HKCU\Software\Valve\Steam\SteamPath`; Epic `HKLM\SOFTWARE\WOW6432Node\Epic Games\EpicGamesLauncher\AppDataPath` + `Manifests`; GOG `HKLM\SOFTWARE\WOW6432Node\GOG.com\Games\<id>`; emulators from `…\Microsoft\Windows\CurrentVersion\Uninstall\*` under HKLM, HKLM WOW6432Node and HKCU) and from files those point to. Read-only; never write launcher files or registry.
- No network, no API keys, nothing to install.
- Tile id = `<source>:<launcher id>` (Steam appid or shortcut gameid, Epic AppName, GOG product id, Xbox AUMID, lower-cased exe path for emulators/apps).
- Sort: `LastPlayed` descending (Steam only), then title A→Z (current culture, case-insensitive). Steam exclusions as Python `STEAM_EXCLUDED_APPIDS` and shortcut flags.
- Launch through the overlay's existing `HideAndRun` path with `ShellOpen.Open(target)`: Steam `steam://rungameid/<id>`, Epic `com.epicgames.launcher://apps/<AppName>?action=launch&silent=true`, GOG registered exe (with its working directory) or its `launchCommand`, Xbox `shell:AppsFolder\<AUMID>`, emulators/apps the exe.
- Config keys: `games_sources_hidden` (list of source ids), `games_manual_apps` (list of exe paths). Text via `Loc.T` both languages. Pad/keyboard/mouse all work (hover selects a tile, click launches, wheel scrolls rows).
- Agents never launch games, launchers or emulators; read-only smoke checks only. Self-test `All N checks passed.`; build 0 warnings; commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **A launcher installed but its library empty or files missing/corrupt** (fresh Epic install, Steam never logged in): that source contributes nothing, no exception, others still load. Tests in Tasks 1-2 with missing/garbled fixtures.
2. **Library refresh while a tile is selected** (a game installed/uninstalled in the background): selection stays on the same game by id, or moves to a neighbour; A never launches a different game than the one shown. Test in Task 3.
3. **Huge libraries (500+ games)** and slow disks: loading never blocks the UI; the grid shows the previous list meanwhile. Task 4 (background service) and a Core test that sorting/filtering 1,000 entries stays fast (< 50 ms).
4. **Filter set to a source that becomes empty** (source hidden in Settings, last Epic game uninstalled): the filter falls back to All. Test in Task 3.
5. **Unicode / special characters in titles and paths** (™, Japanese titles, paths with spaces or `&`): parsed, shown and launched correctly. Tests in Tasks 1-2.

public static class GameLibrary
{

}
